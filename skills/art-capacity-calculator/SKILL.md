# 美术产能与排期

这是一个面向游戏美术 PM 的产能与排期 skill。核心不是“套一个公式”，而是先把管线拆对，再算人天、排依赖、看风险，最后给出可执行的补缺口方案。

## 先问清这些输入

在开始算之前，尽量确认：

1. **管线**：角色 / 场景 / UI，还是多条一起。
2. **范围**：角色数、场景数、UI 界面数；复杂度分档 S/A/B。
3. **标准工时**：每档每道工序的人天；没有就用工具默认值，并标注“待校准”。
4. **人员**：每个资源池的人数、职级、投入比例；兼岗关系。
5. **日历**：启动日期、周末规则、节假日、目标周期、缓冲周。
6. **复用**：组件/模型/材质复用率；模块库/组件库一次性投入。
7. **外包**：单价、损耗、供应商周产能、验收成本。
8. **约束**：哪些工序必须串行、哪些可重叠、哪些批次优先。

如果用户只给一句“帮我排个期”，先按默认值给出**带假设的初版**，再列出需要确认的 3～5 个关键假设。

## 三条管线的拆法

### 角色管线

工序：`原画 → 模型 → 绑定 → 动作 → 特效 → 整合验收`

资源池：

- 原画组
- 模型组
- 绑定组（由动作组里兼做绑定的人承担，不是模型组）
- 动作组
- 特效组
- 整合组

注意：

- 模型和绑定是两个独立资源池；绑定组没人，绑定工序就没有产能。
- 不要把“模型师默认会绑定”写进假设。
- 角色按数量 × 每角色动作组数 / 特效个数展开。

### 场景管线

工序：`概念 → 组件拆分 → 白模 → 组件模型 → 材质 → 地编（资产替换/摆放） → 灯光 → 优化/验收`

资源池：

- 场景原画组：概念 + 组件拆分
- 场景模型组：组件模型 + 材质
- 地编组 / 场景编辑：白模 + 地编 + 灯光 + 优化

关键校验：

- **组件拆分**是原画到模型的交接物，不能省。
- **白模由场景编辑搭**，不是模型组的工作。
- **地编的核心是资产替换、摆放、植被、道具**，不是只“摆白模”。
- 场景计划必须能展开到**单个场景的每道工序**；只有三个资源块不够。
- 场景 WBS 的面积系数、复用率、模块库要能影响计划，不能只是另一张表。

### UI 管线

工序：`UX → 视觉 → 切图 → 动效 → 整合 → 适配 → 验收`

资源池：

- UI 视觉组：UX + 视觉 + 切图
- UI 动效组：动效
- UI 整合组：引擎整合 + 适配 + 验收

注意：

- UI 按“界面 / 功能模块”拆，不按“UI 设计”一个包。
- 组件库是全场一次性投入，先做组件再铺界面。
- 复杂度 S/A/B；复用率降低视觉 / 切图 / 整合 / 适配，不降低 UX / 动效。
- 空态、错误态、加载态、多语言长文本、安全区都要进 WBS。

## 计算模型

### 1. 有效 FTE

```text
有效 FTE = Σ(投入% × 职级系数)
```

职级系数默认：组长 0.6、高级 1.0、中级 1.0、初级 0.9。角色、场景、UI 可以使用各自独立的一套系数。

### 2. 需求人天

```text
需求人天 = 数量 × 单件标准工时 × 复用折减
```

场景还要乘面积系数：

```text
面积系数 = clamp(场景面积 / 基准面积, 0.6, 1.6)
```

模块库 / 组件库是**一次性投入**，只加一次，不参与逐场景/逐界面随机。

### 3. 日历

- 按工作日算，不按自然日。
- 扣周末和节假日。
- 项目工期 = 最后一道工序结束日 + 缓冲周。
- 不要把“周”直接当 7 个自然日。

### 4. 排期

角色管线可以用资源块 + 启动周来排；场景和 UI 更接近**逐任务依赖排期**：

- 每个场景 / 每个界面按工序顺序走。
- 前一道完成，后一道才能开始。
- 同一个资源池的多个任务按批次、场景/界面顺序排队。
- 每个任务有真实开始 / 结束日期，而不是按资源块比例切。

如果只做资源块排期，必须在输出里说明“这是容量视图，不是单场景/单界面的执行排期”。

### 5. 工期与缺口

```text
容量缺口 = Σ max(0, 资源池需求 - 资源池目标周期内产能)
工期折算 = 总人天 × (实际工期 - 目标工期) / 实际工期
总缺口 = max(容量缺口, 工期折算)
```

不要把“容量够但串行等待导致延期”说成“没有缺口”。要区分：

- **容量缺口**：人不够。
- **工期折算**：人够，但依赖/排队导致晚。

### 6. 三点估算

每道工序用乐观 / 最可能 / 悲观做三角分布：

- 固定种子，结果可复现。
- 输出 P50 / P80 / P90 和按期概率。
- 场景 / UI 的模拟要带逐任务依赖，不能只随机总人天。
- P50 高于确定性基准是正常的：三角分布均值大于最可能值。要在结论里解释，不要当成 bug。

### 7. 缺口三解

- **A 加人**：招聘周期 + 爬坡月数 + 爬坡期产能；成本按整人计，不要用小数 FTE 发工资。
- **B 外包**：外包人天 = 缺口 × (1 + 损耗率)；成本 = 外包单价 + 验收成本；受供应商周产能约束。
- **C 砍范围**：按目标 / 实际工期比例保留场景或界面，向下取整。
- **D 延期**：不增加成本，只展示工期代价。

结论要明确：**推荐哪个、为什么、代价是什么、什么情况下不成立**。

## 从策划文档自动拆解

可以，但不要“文档一扔就直接出最终日期”。正确流程是：

```text
策划文档 → 范围 JSON（含假设）→ 确认 → 排期
```

### 支持文档

- Word `.docx`：用 `office-docx` 读取，或 python-docx
- PDF：用 `office-export-pdf` / `office-render`，或 pdftotext
- Excel `.xlsx`：用 `office-xlsx` 读取
- Markdown / 纯文本：直接读
- 飞书 / 在线文档：先导出为 docx / pdf / md

### 执行步骤

1. **读文档**：提取项目类型、系统、角色、场景、UI、节点、约束。
2. **按 schema 填**：使用 `references/scope-schema.md` 的结构，生成 `scope.json`。
3. **标假设**：文档没写的，用 `default` / `inferred` 标注，写进 `assumptions`，不要静默编数。
4. **先确认**：把范围、复杂度、目标周期、人员、复用假设给用户确认；最多列 3～5 个关键假设。
5. **跑排期**：
   ```bash
   node scripts/scope-to-plan.mjs scope.json --out plan.csv
   ```
6. **输出**：摘要表 + 逐任务 CSV + 风险 + 缺口方案。

### 映射规则

- 文档里的“系统 / 界面” → UI 界面清单；复杂系统拆成多个界面。
- 文档里的“地图 / 关卡 / 区域” → 场景清单；按主城/野外/副本分 S/A/B。
- 文档里的“角色 / Boss / 怪物 / NPC” → 角色档位；没有数量就按 S/A/B 估并标注。
- 文档里的“动作 / 技能 / 特效” → 动作组数、特效个数。
- 文档里的“模块库 / 组件库 / 共用资产” → 一次性投入，不摊进逐场景/逐界面随机。
- 文档里的“上线 / 测试 / 版本节点” → 目标周期和批次 P0–P3。

### 不能自动相信的部分

- 策划文档通常不写美术标准工时、人员职级、复用率、外包价格。
- 这些必须用默认值 + 显式假设，或向 PM 确认。
- 自动拆解只能产出**可讨论的初版**，不能替代主美/PM 的范围确认。

`references/scope-template.md` 是给策划/PM 填的输入模板；`examples/scope-example.json` 是完整示例。

## 执行跟踪

排期不是结束，执行页要能回答：

- 基线是多少？
- 现在实际花了多少、完成多少？
- CPI / 预测工期是否偏离？
- 谁请假、谁被其他项目占用？
- 哪些门禁没通过、返工多少？

### 基线 vs 实际

- 先“锁定当前基线”，保存角色 / 场景 / UI 的基线人天、周数、目标、完工日。
- 按周填累计实际人天和完成%。
- 挣值 = 基线人天 × 完成%。
- CPI = 挣值 / 实际人天；小于 1 表示实际消耗高于挣值。
- 预测周 = 基线周 × (实际 + 剩余) / 基线人天。
- 返工人天直接计入实际人天，不要另算一套。

### 人员可用性

- `其他项目%` 用于看跨项目冲突，不从本项目扣产能。
- `请假周` 按全年比例扣减本项目有效 FTE。
- 超配（投入% + 其他项目% > 100）要标红。
- 改完可用性要重算三条管线。

### 质量门禁

- 门禁状态：未开始 / 评审中 / 通过 / 带风险通过 / 驳回。
- 记录轮次、反馈数、返工人天、评审人、日期、风险备注。
- 门禁不通过，不应进入下一道工序；带风险通过必须写清风险。
- 返工是排期最大的隐形变量，必须单独汇总。

## 工作流

1. **识别管线与问题类型**
   - 算产能 / 排期 / 审工具 / 做缺口方案，输出重点不同。
2. **建立 WBS**
   - 角色按角色 × 工序；场景按场景 × 8 工序；UI 按界面 × 7 工序。
3. **填标准工时与人员**
   - 没有数据就先用默认值，并标注需要 PM 校准。
4. **排依赖**
   - 场景 / UI 优先逐任务；角色可用资源块 + 启动周。
5. **算风险**
   - 三点估算 + 产能波动；检查 P50 / P80 与目标的关系。
6. **给方案**
   - 加人 / 外包 / 砍范围 / 延期，四选一并说明代价。
7. **输出**
   - 假设、WBS、产能、排期、风险、方案、待确认项。

## 专业校验清单

排期或工具出现以下情况时，要主动指出：

- 绑定组被默认成模型组的人。
- 白模被算在场景模型组，而不是场景编辑。
- 场景计划只有三个资源块，看不到单场景工序。
- WBS 改了面积/工时，但计划、风险、缺口、台账没跟着变。
- 场景数改了，清单和计划各算各的。
- 三点估算把模块库/组件库当随机量。
- 缺口三解 A 用小数 FTE 算工资，却按整人招聘。
- 场景/UI 缺人组没有提示，风险结果反而更乐观。
- UI 没有组件库、空态/错误态、适配、多语言。
- 排期只按自然日，不扣周末/节假日。

更完整的审计项见 `references/audit-checklist.md`。

## 使用工具

交互版在：

```text
assets/art-capacity-calculator.html
```

用法：

1. 用 Chrome / Edge 打开。
2. 先设启动日、目标周期、节假日。
3. 在「人力产能」里维护人员；角色、场景、UI 各自独立。
4. 在任务拆解页填数量/工时；计划排期页自动出日期。
5. 需要交付时导出 CSV。

数据只存在浏览器 `localStorage`，不会上传。换电脑前先导出。

如果当前环境不能开浏览器：

- 用 `references/methodology.md` 里的公式手算。
- 把关键输入和结果写成表格，标注“未跑交互工具”。
- 不要假装打开过 HTML 或读过其中数据。

## 输出格式

建议按这个结构回答：

```markdown
## 结论
一句话：能不能按期、卡在哪、要补多少。

## 关键假设
- 范围 / 标准工时 / 人员 / 日历 / 复用 / 外包

## 产能与排期
| 管线 | 总人天 | 目标 | 建议工期 | 缺口 | 卡点 |

## 风险
P50 / P80 / 按期概率 / 主要波动源

## 方案
| 方案 | 做法 | 工期 | 成本 | 代价 |

## 建议
推荐方案 + 触发条件 + 需要 PM 确认的点
```

数字要给单位；结论要区分“容量缺口”和“工期折算”；不要只给一个“大概”。
