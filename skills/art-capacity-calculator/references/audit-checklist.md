# 排期 / 工具审计清单

按严重度从高到低检查。

## P0：会让数字不可信

- 绑定组被默认成模型组的人；实际绑定应由动作组兼任。
- 白模被算在场景模型组；实际白模由场景编辑搭建。
- 场景计划只有资源块，看不到单个场景的工序和日期。
- WBS 的面积 / 工时改了，但计划、风险、缺口、台账没重算。
- 场景清单数量与计划数量不一致，两边各算各的。
- 三点估算把模块库 / 组件库一次性投入当随机量。
- 缺口三解 A 用小数 FTE 算工资，但按整人招聘。
- 场景 / UI 缺人组未提示，风险结果反而更乐观。
- 排期按自然日，不扣周末 / 节假日。

## P1：刷新与同步

- WBS 加 / 删 / 改等级后，任务表不刷新。
- 场景清单和资产台账双向不同步：状态、负责人、名称、批次改一边，另一边旧。
- 重建清单 / 重置台账后，另一个视图不刷新。
- 场景数改了，资产台账仍显示旧数量，且无提示。
- UI 改界面复杂度后，排期 / 人力 / 任务表没有同步。
- 角色 / 场景 / UI 系数互相串：改一个管线影响另一个。

## P2：口径与模型

- 卡点组（最晚结束）和容量瓶颈（总需求/产能）混用。
- “容量缺口”和“工期折算”混在一起，结论说“产能够”但 KPI 显示缺口。
- 三角分布的 P50 高于确定性基准，没有解释。
- 复用只降低部分工序，却把全部工序都打折。
- 面积系数没有上下限，导致 0 面积也算工时。
- 外包供应商产能无上限，或为 0 时工期算成目标周期。
- 加人方案没有招聘/爬坡延迟，或延迟后比不补人还晚却没标注。
- 角色按“角色数 × 单角色工时”算，但动作/特效没有按组数/个数展开。
- UI 没有组件库、空态 / 错误态 / 加载态、多语言、安全区。

## P3：体验与可维护性

- 单文件 HTML 里重复 ID。
- 表格列数和表头不一致。
- 大列表每次输入都全量重绘，输入框失焦。
- 导出 CSV 与界面口径不一致。
- 数据只存 localStorage，没有导出提醒。
- 旧数据迁移没有提示，人员组被悄悄改掉。

## 快速验证

1. 改一个场景面积，计划总人天是否变化？
2. 改一个场景数量，清单 / 任务表 / 台账是否同步？
3. 改一个 UI 界面复杂度，UI 排期是否变化？
4. 把某资源池人数设为 0，是否出现缺人提示？
5. 改角色职级系数，场景 / UI 是否不受影响？
6. 导出 CSV，和界面数字对一遍。
7. 刷新页面，数据是否恢复？
